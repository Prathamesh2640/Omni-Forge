## Section 3 — Loopholes, bugs and upgrades

### 3.1 PDF compression destroys embedded images — **VERIFIED, P0**
`modules/converters/pdf_suite/logic.py:358`
```python
document.update_stream(xref, shrunk.tobytes("jpeg", jpg_quality=quality))
```
`update_stream` re-Flates the payload and leaves `/Filter`, `/Width`, `/Height` describing the
*original* image. Repro on a 1200×900 JPEG: output renders **99.6 % black** (content gone),
61,287 B → 4,450 B — the "compression" is data loss.

Fix (verified): `page.replace_image(xref, stream=shrunk.tobytes("jpeg", jpg_quality=quality))`
→ proper `DCTDecode` 600×450 object, 13,881 B, render differs from the source only by resampling.

### 3.2 Process Manager's first CPU sort is meaningless — **VERIFIED, P1**
`modules/system_matrix/process_manager/logic.py:158` — `psutil` returns `0.0` for every process on
the first `cpu_percent` read per `Process` object. Measured here: **0 of 229 processes non-zero.**
`list_processes` is on-demand, so a single Refresh sorted by CPU shows an arbitrary order.
Fix: prime (`process_iter(['cpu_percent'])`, ~0.3 s, re-read) or default the sort to memory until primed.

### 3.3 Unreachable `WAIT_FAILED` branch — **VERIFIED, P2**
`core/permission_manager.py:294` compares a ctypes return against `0xFFFFFFFF`; the default
`restype` is signed `c_int`, so a failed wait returns `-1` and never matches (confirmed).
Fix: `kernel32.WaitForSingleObject.restype = wintypes.DWORD`.

### 3.4 The recycle store is write-only — **P0**
`purge_expired()`, `restore_batch()` and `list_batches()` have **zero production call sites**
(only tests). Consequences:
1. **Nothing is ever freed.** cache_purger reporting "Purged 5 locations, reclaiming 5.0 GB" moved
   5 GB into `data/recycle/` — same disk, still occupied. Same for duplicate_finder and file_filter.
2. **B-04's 24-hour undo is unreachable** — no UI lists or restores a batch.
3. **Unbounded growth.** Evidence on this machine: `data/recycle/20260722_192554_346567` is ~27 h old
   and still present.

Fix: call `purge_expired()` on startup (`app._on_startup`), and add a small "Recycle Bin" panel
(list batches → Restore / Delete now) — the store API already supports all of it.

### 3.5 Recycling across volumes silently copies gigabytes — **P0**
The store lives at `APP_ROOT/data/recycle`. On this box the app is on `D:` and Gradle/Maven/pip
caches are on `C:` — `shutil.move` degrades to full copy+delete, multi-GB, no progress
(`cache_purger.execute` emits exactly two events), and it can fill the app's drive.
Fix: recycle to a per-volume store (`<drive>/.omniforge-recycle`), or detect `st_dev` mismatch and
warn in the confirmation dialog with the real cost.

### 3.6 file_filter "Move" needs 2× the space and frees none — **P1**
`modules/extractors/file_filter/logic.py:318-330` — copies every file to `exports/`, then recycles
the originals. A 5 GB move ⇒ 5 GB copy + 5 GB still in `data/recycle` = 10 GB used, 0 freed.

### 3.7 The sandbox is never used — **P1**
`SandboxTask`, `run_with_timeout`, `CancelRequest`, `ExecuteRequest` and `BaseModule.execute()`
have no production call sites — the only `module.execute(...)` in the tree is a docstring example
(`core/sandbox.py:90`). Every module's `_on_execute` iterates `self.execute(...)` directly. Therefore:
- **B-02's 300 s timeout never applies** to any module operation;
- **cooperative cancellation is unreachable** — no module UI has a Cancel/Stop button (grep: only two
  dialog-dismiss "Cancel"s exist);
- `BaseModule.execute()` exists solely to satisfy conformance tests.

Fix: either route `_on_execute` through `SandboxTask` (gains timeout + a real Cancel button), or
delete the dead API and drop the B-02 claim from the README. The first is the better trade.

### 3.8 B-07 write confinement enforced in 3 of 18 modules — **P1**
`validate_write_target` is called only by crypto_toolkit, network_scanner and secret_scanner.
The other 15 write wherever `params.output_dir` points. `test_architecture.py` doesn't check B-07,
B-01 or B-02 — the rules that actually matter at runtime are the ones with no executable test.

### 3.9 Module instances are singletons holding per-client UI state — **P2**
The registry caches one instance per module; `build_ui()` rebinds `self._progress_bar`,
`self._result_card`, … to whichever client rendered last. A second browser tab (or a reload in
`--browser` mode) silently steals the event handlers from the first. Invisible in native
single-window mode, real in browser mode.

### 3.14 Deliberately skipped
- **Stall watchdog** (`WATCHDOG_STALL_SECONDS` is defined but unused) — the only subprocess work is FFmpeg, which already has its own timeout; a generic no-progress killer over async generators would add risk, not safety.
- **Auto-updater / telemetry / crash reporting** — barred by C-01/C-02 anyway.
- **`get_preview()`** — no consumer; adding it now is speculative API.
- **`i18n.py`** — premature before the UI stops changing.
- **MD→PDF / MD→DOCX** — needs LaTeX or a Pandoc binary; belongs with Phase 8 bundling.
- **rembg background removal end-to-end** — 170 MB model; the degrade-with-guidance path is correct.
- **Auto-elevation for killing access-denied processes** — reporting the refusal is the safer default.
